# FASE 1 — INTERPRETACIÓN DEL PDF

Antes de desarrollar, convierte las instrucciones del PDF en una checklist técnica.

Debes validar explícitamente:

## PASO 1 — ¿ML?

Debe existir:

* problema real;
* objetivo;
* variable objetivo;
* explicación de por qué Machine Learning tiene sentido;
* regla manual / baseline humano;
* comparación posterior contra esa regla.

## PASO 2 — DATOS

Debemos documentar:

* fuente;
* URL;
* quién publica los datos;
* licencia si está disponible;
* método de descarga;
* si provienen de archivo, API o varias fuentes;
* qué representa cada fila;
* número de filas;
* número de columnas;
* variable objetivo;
* justificación de por qué vale la pena predecirla.

La guía también indica que utilizar varias fuentes/tablas y tener que construir una tabla principal aumenta la complejidad del proyecto.

## PASO 3 — LIMPIEZA

Debemos demostrar:

* valores faltantes;
* duplicados;
* tipos de datos;
* formatos;
* valores inconsistentes;
* posibles outliers;
* posibles fugas de información;
* decisiones de limpieza;
* justificación de cada transformación.

Cuando tenga sentido, compara diferentes estrategias para valores faltantes y muestra su efecto.

## PASO 4 — COLUMNAS

Debemos explicar:

* qué columnas entran;
* cuáles se eliminan;
* cuáles se crean;
* por qué;
* qué transformaciones se aplican;
* cómo se manejan fechas;
* texto;
* categorías;
* escalas;
* transformaciones logarítmicas si son apropiadas.

MUY IMPORTANTE:

Las transformaciones que puedan aprender información del dataset deben estar dentro de un Pipeline/ColumnTransformer apropiado para evitar data leakage.

## PASO 5 — MODELOS

Debemos comparar:

* baseline;
* regla manual;
* varios modelos;
* familias de modelos diferentes cuando tenga sentido.

Todos los modelos deben utilizar:

* los mismos datos;
* la misma estrategia de validación;
* el mismo criterio de evaluación;
* preprocessing correctamente integrado.

## PASO 6 — EVALUACIÓN

Debemos:

* seleccionar métricas apropiadas;
* comparar todos los modelos;
* comparar contra baseline/regla manual;
* justificar la elección final;
* explicar por qué el modelo elegido es adecuado.

NO elegir automáticamente el modelo con el número más alto.

# FASE 7 — DATA LEAKAGE

Haz una auditoría específica de leakage.

Para cada feature pregunta:

"¿Esta información estaría disponible en el momento real en que quiero realizar la predicción?"

Si la respuesta es NO:

* eliminarla;
* transformarla;
* o explicar por qué no puede utilizarse.

Todo preprocessing que dependa de los datos debe ajustarse solamente con los datos de entrenamiento.

Utiliza Pipeline / ColumnTransformer cuando sea apropiado.

NO permitas:

* imputación utilizando todo el dataset antes del split;
* scaling usando todo el dataset;
* encoding aprendido usando test;
* selección de variables usando test;
* features calculadas usando información posterior al objetivo.

# REGLAS IMPORTANTES

## Regla 1 — No inventar resultados

Nunca escribas:

"El modelo obtuvo 92 %"

si no lo ejecutaste realmente.

Los resultados deben provenir de una ejecución real.

## Regla 2 — No inventar datos

No crear datasets ficticios para hacer parecer que el proyecto funciona.

## Regla 3 — No copiar los ejemplos

Los ejemplos son material de referencia.

Reutiliza ideas y técnicas cuando sean apropiadas, pero adapta todo al problema final.

## Regla 4 — No sobreingeniería

Este es un proyecto académico.

No quiero una arquitectura empresarial innecesariamente compleja.

Quiero máxima claridad y calidad metodológica.

## Regla 5 — Priorizar explicabilidad

Debo poder explicar presencialmente:

* de dónde vienen los datos;
* qué limpié;
* por qué lo limpié;
* qué columnas utilicé;
* qué modelos probé;
* qué métrica utilicé;
* por qué elegí el modelo final.

## Regla 6 — No ocultar decisiones

Si existe una decisión importante, documentarla.

Por ejemplo:

"Se utilizó mediana en lugar de media porque..."

o:

"Se eliminó esta variable porque..."

## Regla 7 — No hacer cambios destructivos

Antes de modificar archivos existentes:

* analizarlos;
* conservar información útil;
* evitar borrar ejemplos originales.

## Regla 8 — Si falta información, detente

Si no puedes determinar algo importante:

NO inventes.

Indica:

* qué falta;
* por qué importa;
* qué alternativas existen.
